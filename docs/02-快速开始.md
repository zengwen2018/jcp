# 02 · 快速开始

## 1. 环境要求

| 组件 | 版本 | 必需 | 说明 |
|------|------|------|------|
| Go | ≥ 1.24.4 | 是 | 后端构建 |
| Node.js | ≥ 18（推荐 22） | 是 | 前端构建 |
| 图形环境 | — | 桌面模式需要 | Web 模式不需要 |
| 网络 | 可访问行情源 | 是 | 通达信服务器、东方财富等 |

### 国内网络环境

```bash
export GOPROXY="https://goproxy.cn,direct"   # Go 依赖加速
```

Go 安装若 `winget` 失败（直连 go.dev 常报 `0x80072f19`），改用镜像下载 zip：

```bash
curl -L -o go.zip https://mirrors.aliyun.com/golang/go1.24.4.windows-amd64.zip
# 用 Python 解压（Windows 内置 Expand-Archive 可能解压不完整）
python -c "import zipfile; zipfile.ZipFile('go.zip').extractall(r'D:\Program Files')"
```

## 2. 构建

### 2.1 前端

```bash
cd frontend
npm install
npm run build          # 产物输出到 frontend/dist
```

`npm run build` 会执行 `tsc && vite build`——**类型检查失败会中断构建**，这是有意的质量闸门。

### 2.2 后端

```bash
# Web 服务模式（部署用）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -tags web \
  -ldflags "-s -w -X main.Version=$(git describe --tags --always)" \
  -o jcp-server .

# Windows 本地调试
go build -tags web -o jcp-server.exe .

# 桌面模式
go build .              # 或 wails build 生成安装包
```

> **build tag 是关键**：不加 `-tags web` 会编译出桌面版，在服务器上运行会因缺少图形环境而失败。

## 3. 运行

### 3.1 Web 模式

```bash
export JCP_ADDR=":8080"
export JCP_AUTH_TOKEN="$(openssl rand -hex 32)"   # 生成访问令牌
export JCPDATA_DIR="/opt/jcp/data"
export JCP_STATIC_DIR="/opt/jcp/static"           # 可选，默认用内嵌资源

./jcp-server
```

访问：`http://<服务器IP>:8080/?token=<JCP_AUTH_TOKEN>`

首次访问时前端会把 URL 里的令牌存入 `localStorage`，之后直接访问 `http://<IP>:8080/` 即可。

### 3.2 桌面模式

```bash
go run .        # 或 wails dev
```

### 3.3 环境变量完整列表

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `JCP_ADDR` | `:8080` | HTTP 监听地址 |
| `JCP_AUTH_TOKEN` | 空 | 访问令牌。**空 = 不鉴权**（仅限本地调试） |
| `JCP_CORS_ORIGINS` | 空 | 允许的跨域来源，逗号分隔。空 = 仅同源 |
| `JCPDATA_DIR` | `~/.config/jcp` | 数据目录 |
| `JCP_STATIC_DIR` | 内嵌 | 前端静态资源目录 |

## 4. 首次配置

Web 模式启动后数据目录是空的，需要在界面上完成配置。

### 4.1 配置 AI 模型（必做）

进入 **设置 → AI 配置**，添加一个模型：

| 字段 | 说明 | 示例 |
|------|------|------|
| 名称 | 显示名 | `DeepSeek` |
| Provider | `openai`（兼容绝大多数国产模型） | `openai` |
| Base URL | API 端点 | `https://api.deepseek.com/v1` |
| API Key | 密钥 | `sk-xxx` |
| 模型名 | 模型标识 | `deepseek-chat` |
| Max Tokens | 单次最大 token | `4096` |
| Temperature | 采样温度 | `0.7` |
| 超时 | 秒 | `60` |
| 设为默认 | 勾选后成为默认模型 | — |

**要点**

- 密钥保存在**服务端**（`config.json`），浏览器只读得到 `********`
- 多个模型可并存，在专家配置里按 `AIConfigID` 分别指定
- 点「测试连接」验证可用性

### 4.2 配置专家（必做）

进入 **设置 → 策略**，编辑策略中的专家：

- **角色提示词（Instruction）** —— 决定专家的思考方式，这是效果的关键
- **可用工具** —— 勾选该专家能调用的工具，实现角色隔离
- **使用的模型** —— 可为不同专家指定不同模型

内置策略通常已包含基础专家角色，可直接使用或改写。

### 4.3 添加自选股

左侧面板搜索股票代码或名称（如 `600000` 或 `浦发`），加入自选。

自选股是推送订阅的默认来源——服务启动时会自动订阅自选股列表。

## 5. 验证部署

```bash
# 健康检查（无需鉴权）
curl http://127.0.0.1:8080/api/health
# {"status":"ok","version":"0.3.5","time":"..."}

# 鉴权验证
curl -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/api/config
# 401 —— 无令牌被拒

curl -H "Authorization: Bearer $JCP_AUTH_TOKEN" http://127.0.0.1:8080/api/config
# {"data":{...}}

# SSE 连通性
curl -N -H "Authorization: Bearer $JCP_AUTH_TOKEN" http://127.0.0.1:8080/api/events
# data: {"event":"connected","data":{"ok":true}}
```

## 6. 常见问题

**Q：服务启动报 `no matching files found`（pattern all:frontend/dist）**

前端还没构建。先执行 `cd frontend && npm run build`。

**Q：SSE 能连上但收不到行情事件**

按顺序检查：
1. 是否调用了 `GET /api/frontend/ready`（推送循环在等这个信号）
2. 是否调用了 `POST /api/market/subscribe` 订阅股票
3. 是否处于交易时段（收盘时段股票推送 30 秒一次，观察窗口要 ≥40 秒）

**Q：界面上"市场已收盘"，但 A 股明明在交易**

服务端从 `cdn.jsdelivr.net` 拉取节假日数据，该域名在国内可能不可达。表现是市场状态判断错误（不影响行情数据本身）。解决办法：换用可达的镜像源，或改用本地节假日数据。

**Q：前端构建报 TS 错误**

`npm run build` 会先跑 `tsc`。类型错误必须修复——不要用 `tsc || true` 绕过。
