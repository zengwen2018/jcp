# 08 · 部署运维

## 1. 部署形态选择

| 形态 | 适用 | 优点 | 缺点 |
|------|------|------|------|
| **Docker Compose** | 大多数场景 | 环境隔离、一键升级、依赖完整 | 需装 Docker |
| **systemd + 二进制** | 极简环境 | 无容器开销、启动快 | 需手动装 Nginx/证书 |
| **本地运行** | 开发调试 | 最快 | 无公网访问 |

**资源参考**（2核2G 轻量应用服务器实测）：

| 指标 | 占用 |
|------|------|
| 内存（空闲） | 60-90 MB |
| 内存（运行中，含行情推送） | 150-250 MB |
| 磁盘（完整镜像） | 300-500 MB |
| CPU（空闲） | ~1% |
| 二进制大小 | 77 MB（未裁剪）/ 63 MB（`-ldflags "-s -w"`） |

> ⚠️ **不要在 2GB 机器上 `go build`**。Go 编译期内存需求远超运行期，会被 OOM Kill。
> 正确做法：本地交叉编译 → 上传二进制；或用 Docker 构建（构建在容器内完成后只留运行镜像）。

## 2. Docker Compose 部署（推荐）

### 2.1 准备

```bash
# 上传代码
scp -r jcp/ root@<服务器IP>:/opt/jcp-src/
ssh root@<服务器IP> 'cd /opt/jcp-src'

# 创建环境变量文件
cat > .env <<'EOF'
JCP_AUTH_TOKEN=CHANGE_ME
JCP_CORS_ORIGINS=
VERSION=0.3.5
EOF

# 生成强随机令牌
sed -i "s/CHANGE_ME/$(openssl rand -hex 32)/" .env
```

### 2.2 启动

```bash
docker compose -f docker-compose.web.yml up -d --build
docker compose -f docker-compose.web.yml logs -f
```

### 2.3 compose 配置要点

```yaml
ports:
  # 只监听回环，公网流量统一由 Nginx 承接
  - "127.0.0.1:10001:10001"
volumes:
  - ./data:/app/data      # 数据持久化
environment:
  JCP_AUTH_TOKEN: ${JCP_AUTH_TOKEN:-}
  JCP_CORS_ORIGINS: ${JCP_CORS_ORIGINS:-}
  TZ: "Asia/Shanghai"
```

**不要**把 10001 映射到 `0.0.0.0`——那会让应用绕过 Nginx 直接暴露公网。

### 2.4 访问

```
http://<服务器IP>:10001/?token=<JCP_AUTH_TOKEN>
```

## 3. systemd + 二进制部署

### 3.1 本地交叉编译

```bash
export PATH="/d/Program Files/go/bin:$PATH"      # Windows
export GOPROXY="https://goproxy.cn,direct"

cd frontend && npm install && npm run build && cd ..

CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -tags web \
  -ldflags "-s -w -X main.Version=$(git describe --tags --always)" \
  -o jcp-server .
```

### 3.2 一键脚本

```bash
bash deploy/deploy.sh <服务器IP> root
```

脚本自动完成：构建前端 → 交叉编译 → 上传 → 创建 `jcp` 用户 → 安装 systemd → 生成令牌 → 启动服务。

输出形如：

```
==============================================
 部署完成
==============================================
 服务地址 : http://120.53.8.253:10001
 访问令牌 : 3f8a...（64位十六进制）
==============================================
```

### 3.3 手动部署步骤

```bash
# 上传
scp jcp-server root@<IP>:/tmp/
scp -r frontend/dist/* root@<IP>:/tmp/dist/

# 服务器上安装
ssh root@<IP> <<'EOF'
useradd -r -s /sbin/nologin jcp
mkdir -p /opt/jcp/data /opt/jcp/static
mv /tmp/jcp-server /opt/jcp/
cp -r /tmp/dist/* /opt/jcp/static/
chmod +x /opt/jcp/jcp-server
chown -R jcp:jcp /opt/jcp

# 生成令牌
openssl rand -hex 32 > /etc/jcp-token
chmod 600 /etc/jcp-token

# 安装 systemd
sed "s|CHANGE_ME|$(cat /etc/jcp-token)|" deploy/jcp-web.service \
  > /etc/systemd/system/jcp-web.service
systemctl daemon-reload
systemctl enable --now jcp-web
EOF
```

### 3.4 systemd 关键配置

```ini
[Service]
User=jcp
Environment="JCP_AUTH_TOKEN=<token>"
Environment="JCPDATA_DIR=/opt/jcp/data"
Environment="JCP_STATIC_DIR=/opt/jcp/static"
ExecStart=/opt/jcp/jcp-server
Restart=always
RestartSec=5

# 安全加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/jcp/data
```

`ProtectSystem=strict` 需要 `ReadWritePaths` 显式声明可写目录，否则服务无法写数据。

## 4. Nginx 反向代理

### 4.1 关键：SSE 配置

```nginx
location /api/events {
    proxy_pass http://jcp_backend;
    proxy_http_version 1.1;

    proxy_buffering off;           # 必须
    proxy_cache off;
    chunked_transfer_encoding off;

    proxy_read_timeout 3600s;      # 必须
    proxy_send_timeout 3600s;

    proxy_set_header Connection "";  # 必须

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

完整配置见 `deploy/nginx.conf`。

### 4.2 无域名场景

没有域名时，直接用 IP + 端口访问：

```nginx
server {
    listen 80;
    server_name _;          # 或直接省略 server_name

    location /api/events { ... }   # SSE 专用
    location /api/ { ... }         # 普通 API，超时 300s
    location / { ... }             # 静态资源
}
```

此时**没有 HTTPS**，令牌会明文传输。只建议在受控网络或临时使用。

### 4.3 有域名场景

配置证书后启用 HTTPS，并把 80 端口改为跳转：

```nginx
server {
    listen 80;
    server_name jcp.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name jcp.example.com;

    ssl_certificate     /etc/nginx/ssl/jcp.crt;
    ssl_certificate_key /etc/nginx/ssl/jcp.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_session_cache   shared:SSL:10m;

    # location 块同上
}
```

## 5. 防火墙配置

### 5.1 腾讯云控制台

在**轻量应用服务器控制台 → 防火墙** 添加规则：

| 应用类型 | 协议 | 端口 | 来源 | 说明 |
|---------|------|------|------|------|
| SSH | TCP | 22 | 你的 IP/32 | 不要开放 0.0.0.0/0 |
| HTTP | TCP | 80 | 0.0.0.0/0 | 仅当用 Nginx 对外 |
| HTTPS | TCP | 443 | 0.0.0.0/0 | 同上 |

若使用 Nginx 反代，10001 也不必在控制台开放（应用只监听 `127.0.0.1`）。

无域名直接访问的场景下，需要开放 10001：

| 应用类型 | 协议 | 端口 | 来源 |
|---------|------|------|------|
| 自定义 | TCP | 10001 | 0.0.0.0/0（或限制来源 IP） |

### 5.2 服务器内部防火墙

```bash
# Ubuntu (ufw)
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable

# CentOS (firewalld)
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --reload
```

## 6. 运维操作

### 6.1 常用命令

```bash
# systemd 部署
systemctl status jcp-web
systemctl restart jcp-web
journalctl -u jcp-web -f              # 实时日志
journalctl -u jcp-web --since "1 hour ago"

# Docker 部署
docker compose -f docker-compose.web.yml ps
docker compose -f docker-compose.web.yml logs -f
docker compose -f docker-compose.web.yml restart
```

### 6.2 令牌管理

令牌存放在 `/etc/jcp-token`（systemd 部署）：

```bash
# 查看
cat /etc/jcp-token

# 重置
openssl rand -hex 32 > /etc/jcp-token
systemctl restart jcp-web
```

重置后旧令牌立即失效，浏览器需用新令牌重新访问（`?token=<新令牌>`）。

### 6.3 数据备份

```bash
# 定时备份（每天 3:17）
cat > /etc/cron.d/jcp-backup <<'EOF'
17 3 * * * root tar czf /opt/jcp/backups/jcp-$(date +\%Y\%m\%d).tar.gz \
    -C /opt/jcp/data config.json strategies.json sessions memories
EOF

# 清理 30 天前的备份
find /opt/jcp/backups -name "jcp-*.tar.gz" -mtime +30 -delete
```

### 6.4 升级流程

```bash
cd /opt/jcp-src
git pull
docker compose -f docker-compose.web.yml up -d --build    # Docker
# 或
bash deploy/deploy.sh <服务器IP> root                       # 二进制
```

数据目录（volume 挂载）不受升级影响。

### 6.5 资源监控

```bash
# 容器
docker stats --no-stream

# systemd
systemctl status jcp-web
ps -o pid,rss,etime,cmd -p $(pidof jcp-server)

# 轻量服务器控制台自带监控
# 关注：CPU、内存、带宽出流量、流量包使用量
```

## 7. 故障排查

### 7.1 服务起不来

```bash
journalctl -u jcp-web -n 50
```

| 日志关键字 | 原因 | 处理 |
|-----------|------|------|
| `no matching files found` | 前端未构建 | `cd frontend && npm run build` |
| `pattern ... conflicts` | 路由重复注册 | 检查 `internal/webapi/routes.go` |
| `permission denied` | 数据目录权限 | `chown -R jcp:jcp /opt/jcp/data` |
| `address already in use` | 端口被占 | `ss -lntp | grep 10001` |

### 7.2 能访问但没数据

按顺序排查：

```bash
# 1. 服务端能取到行情吗
curl -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:10001/api/stock/realtime?codes=sh600000"

# 2. SSE 连得上吗
curl -N -H "Authorization: Bearer $TOKEN" http://127.0.0.1:10001/api/events

# 3. 前端是否调用了 ready + subscribe
```

若是**服务端取不到行情**：检查服务器出网能力——行情源需要访问通达信服务器。

### 7.3 SSE 延迟几十秒

几乎总是 `proxy_buffering` 没关。检查 Nginx 配置。

### 7.4 内存不足

```bash
free -h
docker stats --no-stream
```

- 减少同时打开的浏览器标签页（每个标签页一个 SSE 连接）
- 关闭记忆系统的摘要压缩（用大模型做摘要会吃内存）
- 降低 `maxRecentRounds` / `maxKeyFacts`

### 7.5 市场状态判断错误

服务端从 `cdn.jsdelivr.net` 拉节假日数据，该域名在境内常不可达。表现是"明明在交易却显示已收盘"。

不影响行情数据本身，只影响时段判断（推送频率降级）。

## 8. 上线检查清单

- [ ] `JCP_AUTH_TOKEN` 已设置为强随机值（≥32 字节）
- [ ] `JCPDATA_DIR` 已设置且指向持久化目录
- [ ] `config.json` 权限为 `600`
- [ ] 服务以非 root 用户运行
- [ ] 云防火墙仅放行 22 与业务端口（无反代时为 10001）
- [ ] Nginx 的 `proxy_buffering off` 已配置
- [ ] `proxy_read_timeout` ≥ 3600s
- [ ] 数据备份 cron 已配置
- [ ] 健康检查可用：`curl http://127.0.0.1:10001/api/health`
- [ ] 已完成 AI 模型配置并测试连通
- [ ] （有域名）HTTPS 证书已配置且自动续期
