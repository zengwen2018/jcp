# 07 · 数据存储

JCP **不使用数据库**，全部数据以 JSON 文件落盘。本文说明目录布局、数据模型与持久化策略。

---

## 1. 存储总览

### 1.1 数据目录

```
$JCPDATA_DIR/                  默认 ~/.config/jcp
├── config.json                全局配置（含 AI 配置明文密钥）
├── watchlist.json             自选股列表
├── strategies.json            策略仓库（含专家配置）
├── sessions/                  会话（每只股票一个文件）
│   ├── sh600000.json
│   └── sz000001.json
├── memories/                  长期记忆（每只股票一个文件）
│   ├── sh600000.json
│   └── sz000001.json
├── logs/                      日志文件
│   └── app.log
└── cache/                     缓存
    └── ...
```

目录解析逻辑（`internal/pkg/paths/paths.go`）：

```go
func GetDataDir() string {
    if dir := os.Getenv("JCPDATA_DIR"); dir != "" {
        return dir            // ① 环境变量优先
    }
    userConfigDir, err := os.UserConfigDir()
    if err != nil || userConfigDir == "" {
        return filepath.Join(".", "data")   // ③ 兜底
    }
    return filepath.Join(userConfigDir, "jcp")  // ② 系统配置目录
}
```

| 平台 | 默认路径 |
|------|---------|
| Linux | `~/.config/jcp` |
| macOS | `~/Library/Application Support/jcp` |
| Windows | `%AppData%\jcp` |

**部署时务必设置 `JCPDATA_DIR`**，否则数据落在 root 家目录，不便挂载持久化卷。

### 1.2 目录职责

| 目录/文件 | 归属 | 内容 | 可重建 |
|-----------|------|------|--------|
| `config.json` | `ConfigService` | 全局配置、AI 密钥、代理、记忆设置 | ❌ 丢失即失配置 |
| `watchlist.json` | `ConfigService` | 自选股 | ✅ |
| `strategies.json` | `StrategyService` | 策略与专家定义 | ⚠️ 内置策略会重新生成 |
| `sessions/` | `SessionService` | 聊天记录 | ✅ |
| `memories/` | `memory.FileStorage` | 长期记忆 | ✅ |
| `logs/` | `logger` | 运行日志 | ✅ |
| `cache/` | `paths.EnsureCacheDir` | 各类缓存 | ✅ |

## 3. 持久化策略

### 3.1 读写模式

```go
// ConfigService.UpdateConfig
data, err := json.MarshalIndent(cs.config, "", "  ")   // 格式化，便于人工检查
err = os.WriteFile(cs.configPath, data, 0644)
cs.config = config
```

三个特点：

1. **读多写少** —— 启动时载入内存，日常读操作走内存加读锁
2. **写时序列化** —— `MarshalIndent` 缩进两格，方便直接 cat 查看
3. **先写盘再更新内存** —— 避免内存已改但落盘失败的中间态

### 3.2 并发保护

每个 Service 持有自己的 `sync.RWMutex`：

```go
type ConfigService struct {
    config *models.AppConfig
    mu     sync.RWMutex
}
```

- 读操作 `RLock` / `RUnlock`
- 写操作 `Lock` / `Unlock`

`MarketDataPusher` 的并发更复杂，订阅状态与推送状态分别用不同的锁：

```go
mu            sync.RWMutex   // subscribedCodes / currentOrderBook
klineSubMu    sync.RWMutex   // klineSub / lastKLineTime
ctrlMu        sync.Mutex     // ready / stopped 生命周期
pushMu        sync.Mutex     // 防止 runParallel 重入堆积
```

### 3.3 写入原子性

**当前实现不是原子写**（直接 `os.WriteFile`）。进程在写入过程中被 kill，可能留下截断的 JSON。

风险评估：

- 写入是瞬时操作（配置文件通常 <10KB）
- 但服务器异常重启或 OOM 时存在小概率损坏

**建议加固**（若要改）：改为「写临时文件 → `os.Rename` 原子替换」。

启动时的容错：JSON 解析失败会回退到默认值并打日志，不会崩溃——但**配置会丢失**。所以备份 `config.json` 很重要。

### 3.4 缓存

股票名称目录等缓存写在 `<dataDir>/cache/` 或数据目录下，带 TTL：

```go
type tdxMarketProvider struct {
    catalog    []StockSearchResult
    nameBySymbol map[string]string
    updatedAt  time.Time
    cacheTTL   time.Duration
    cachePath  string
}
```

缓存可以安全删除，服务会重建。

## 4. 数据生命周期

```
                    ┌──────────────────────────────┐
                    │  内存                        │
                    │  config (AppConfig)          │
                    │  watchlist ([]Stock)         │
                    │  sessions (按需加载)          │
                    └───────────┬──────────────────┘
                                │ 用户修改 / 会议结束
                                ▼
                    ┌──────────────────────────────┐
                    │  JSON 文件                     │
                    │  config.json / watchlist.json │
                    │  sessions/<code>.json          │
                    │  strategies.json               │
                    │  memories/<code>.json          │
                    └──────────────────────────────┘
```

**会话的读写时机**：

- `GetOrCreateSession(code)` —— 从磁盘加载或创建
- `SendMeetingMessage` 完成后 —— 追加消息并写回
- `ClearSessionMessages(code)` —— 清空并写回

**记忆的写入时机**：会议结束后，记忆管理器按 `CompressThreshold` 判断是否需要压缩，用 LLM 提取事实与摘要后覆盖写回。

## 5. 备份与迁移

### 5.1 备份范围

| 需要备份 | 不需要 |
|---------|---------|
| `config.json`（**含密钥**） | `logs/` |
| `strategies.json`（自定义策略） | `cache/` |
| `sessions/`（历史讨论） | |
| `memories/`（长期记忆） | |

### 5.2 备份命令

```bash
tar czf jcp-backup-$(date +%Y%m%d).tar.gz \
    -C /opt/jcp/data \
    config.json strategies.json sessions/ memories/
```

### 5.3 迁移到新服务器

```bash
# 旧服务器
tar czf jcp-data.tar.gz -C /opt/jcp/data config.json strategies.json sessions memories

# 新服务器
scp jcp-data.tar.gz root@<new-ip>:/tmp/
ssh root@<new-ip> 'tar xzf /tmp/jcp-data.tar.gz -C /opt/jcp/data'
```

**注意**：`config.json` 里的 AI 密钥随配置一起迁移，无需重新配置。

### 5.4 权限建议

```bash
chmod 600 /opt/jcp/data/config.json      # 含明文密钥
chown -R jcp:jcp /opt/jcp/data
```

Docker 部署时用 volume 挂载，并把宿主目录权限收紧。

## 6. 并发访问注意

**单进程假设**：JCP 假定只有一个进程访问数据目录。

- 不要同时跑两个实例指向同一 `JCPDATA_DIR`
- systemd 的 `Restart=always` 保证单实例；不要额外配 `Type=forking` 或多 worker
- Docker Compose 部署时不要配置 `deploy.replicas > 1`

## 7. 存储相关故障排查

| 现象 | 检查方向 |
|------|---------|
| 配置改了不生效 | 确认 `JCPDATA_DIR` 指向预期目录；看日志里"加载策略配置成功" |
| 启动报 JSON 解析错误 | 配置文件损坏，用备份恢复 |
| 自选股丢失 | `watchlist.json` 解析失败会回退到空列表 |
| 记忆不生效 | `memory.enabled` 为 false，或未配置 `memory.aiConfigId` |
| 磁盘写满 | `ls -lh /opt/jcp/data/*`；日志与会话会持续增长 |
