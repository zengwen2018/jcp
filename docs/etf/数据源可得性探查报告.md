## 4. 代码改造点评估

### 4.1 Provider 抽象：现有二元结构 → 市场路由

**现状**（`internal/services/market_provider.go`）：
```go
type marketProvider interface {
    FetchStockDataWithOrderBook(codes ...string) ([]StockWithOrderBook, error)
    FetchKLineData(code string, period string, days int) ([]models.KLineData, error)
    FetchMarketIndices() ([]models.MarketIndex, error)
    SearchStocks(keyword string, limit int) ([]StockSearchResult, error)
}
ms.primaryProvider  = newTDXMarketProvider()   // 只支持 SH/SZ/BJ
ms.fallbackProvider = newSinaMarketProvider(ms) // A股+美股(GBK)
```

**问题**：`FetchStockDataWithOrderBook(codes ...string)` 是**批量**签名，一次请求混市场就无法路由；`FetchMarketIndices()` 是**无参**的，无法按市场取指数。

**推荐方案：按市场前缀路由的 Provider Map + 批量请求按市场分组（Chain-of-Responsibility 的变体）**

```go
// internal/services/market_router.go （新增）
type marketProvider interface { /* 保持现有 4 方法签名不变 */ }

type marketRouter struct {
    // 市场前缀 → 该市场的 provider 链
    routes map[string][]marketProvider   // "sh" → [tdx, tencent, sina]
    // 无前缀接口（如指数列表）单独路由
    indexProviders map[string]marketProvider
}

// 路由键：从 symbol 前 2 位取
//   sh / sz / bj → A股
//   us           → 美股
//   etf / lof    → A股场内基金（复用 A股路由，解析器分支）
```

**改动面与理由**：

| 方案 | 改动面 | 优点 | 缺点 |
|---|---|---|---|
| **A. Provider Map（推荐）** | 新增 `market_router.go`（~150行）+ 改造 `market_service.go` 的 4 个 `*WithFallback` 方法（各 +10行） | 1) 批量请求按前缀分组，组内并行 2) 每市场可独立配主/兜底 3) 新增市场只加一个 map 条目 | 需处理"一批代码跨市场"的分组逻辑 |
| B. 链式匹配（Chain of Responsibility） | 改 `marketProvider` 接口加 `Supports(code string) bool` | 天然按优先级 | 批量请求时每 provider 都要收到全部 code 再过滤，浪费配额 |
| C. 按标的类型分派（ETF/股/美股） | 改 `Stock` 模型 + 分派 | 语义清晰 | **代码格式里没有"标的类型"信息**（`sh510300` 光看前缀不知道是 ETF），必须先查目录才知道 → 反向依赖，改造面最大 |

**推荐 A**，理由：现有 `sh/sz/bj` 前缀体系天然就是路由键（腾讯 smartbox 搜索结果也直接返回 `sh~...`/`us~...` 前缀，与本方案一致），且批量接口（腾讯/新浪都支持逗号批量）天然可以**按市场分组后一次请求发完**，网络开销最优。

**必须同时改的签名问题**：
- `FetchMarketIndices()` 无参 → 需改为 `FetchMarketIndices(market string)` 或新增 `FetchMarketIndicesByMarket(market string)`。**这是破坏性改动**，会波及 `market_provider.go`、`market_service.go:962`、`market_provider_tdx.go:189`、新浪实现 `market_service.go:971`。建议**保留旧方法 + 新增带参方法**以免一次改太多。
- `SearchStocks(keyword, limit)` → 美股/ETF 需要返回**类型 + 市场**，现有 `StockSearchResult` 需加字段（见 4.3）。

### 4.4 ETF 特有能力：塞进现有响应还是新接口？

**建议：不塞进现有行情响应，走新接口。** 理由：

1. 现有 `/api/stock/realtime` 是**高频轮询**接口（前端 SSE 推送用），加 IOPV/净值/持仓会让响应体积暴涨（持仓 10 条 + 净值序列）。
2. IOPV 和净值是**不同更新频率**的数据：IOPV 秒级刷新，净值 T+1 披露，规模季度披露。
3. 持仓/规模是**低频静态数据**，应该缓存。

**建议新增端点**（`internal/webapi/routes.go`，现有 60 个端点 → 70 个）：

|---|---|---|---|---|
