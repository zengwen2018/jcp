# 04 · 模块设计

本文按包逐一说明职责、关键类型与调用关系。阅读顺序建议：`models` → `services` → `adk` → `meeting` → `memory` → `agent` → `pkg`。

## 1. `internal/models` — 领域模型

所有跨层传递的数据结构定义在此。**不含逻辑，只有结构体与常量**。

### 1.1 配置模型 `config.go`

```go
type AppConfig struct {
    Theme               string              `json:"theme"`               // military/ocean/purple/orange/dark
    CandleColorMode     string              `json:"candleColorMode"`     // red-up(红涨绿跌)/green-up
    AIConfigs           []AIConfig          `json:"aiConfigs"`
    DefaultAIID         string              `json:"defaultAiId"`
    StrategyAIID        string              `json:"strategyAiId"`        // 策略生成用
    ModeratorAIID       string              `json:"moderatorAiId"`       // 意图分析(小韭菜)用
    AIRetryCount        int                 `json:"aiRetryCount"`
    VerboseAgentIO      bool                `json:"verboseAgentIO"`
    AgentSelectionStyle AgentSelectionStyle `json:"agentSelectionStyle"`
    EnableSecondReview  bool                `json:"enableSecondReview"`
    MCPServers          []MCPServerConfig   `json:"mcpServers"`
    Memory              MemoryConfig        `json:"memory"`
    Proxy               ProxyConfig         `json:"proxy"`
    Layout              LayoutConfig        `json:"layout"`
    OpenClaw            OpenClawConfig      `json:"openclaw"`
    Indicators          IndicatorConfig     `json:"indicators"`
}
```

关键子结构：

```go
type MemoryConfig struct {
    Enabled           bool
    AIConfigID        string  // 摘要用的独立模型
    MaxRecentRounds   int
    MaxKeyFacts       int
    MaxSummaryLength  int
    CompressThreshold int
}

type ProxyConfig struct {
    Mode      ProxyMode  // none / system / custom
    CustomURL string
}
```

**注意**：`AIConfigs[].APIKey` 明文存储于服务端文件，Web 模式下浏览器只拿到 `********`（见 [09-安全模型.md](09-安全模型.md)）。

## 2. `internal/services` — 数据与业务服务

28 个文件、约 9400 行，是最重的部分。

### 2.1 `config_service.go` — 配置持久化

```go
type ConfigService struct {
    configPath    string  // <dataDir>/config.json
    watchlistPath string  // <dataDir>/watchlist.json
    config        *models.AppConfig
    watchlist     []models.Stock
    mu            sync.RWMutex
}
```

- 启动时从 JSON 读取，文件不存在则用默认值
- 读操作走内存（加读锁），写操作先写文件再更新内存
- `MarshalIndent` 格式化存储，便于人工检查

### 2.2 `market_service.go` + `market_provider*.go` — 行情

采用 **Provider 模式**：

```go
type marketProvider interface {
    GetStockRealTimeData(codes ...string) ([]models.Stock, error)
    GetKLineData(code, period string, days int) ([]models.KLineData, error)
    GetOrderBook(code string) (models.OrderBook, error)
    ...
}
```

当前实现 `tdxMarketProvider`（`market_provider_tdx.go`）走**通达信协议**（`github.com/injoyai/tdx`）：

- 股票名称目录缓存到 `<dataDir>/stock_catalog.json`，带 TTL
- 指数代码有内置中文名映射：`sh000001`→上证指数、`sz399001`→深证成指、`sz399006`→创业板指

`market_service.go` 是上层门面，聚合缓存、节假日判断与 Provider 调用。

### 2.3 `market_pusher.go` — 实时推送

**这是 Web 化改造中改动最多的文件**（18 处 `runtime.EventsEmit` → `bus.Emit`）。

```go
type MarketDataPusher struct {
    ctx           context.Context
    marketService *MarketService
    configService *ConfigService
    newsService   *NewsService
    bus           eventbus.EventBus   // ← 新增依赖

    subscribedCodes  []string
    currentOrderBook string
    klineSub         KLineSubscription
    ready            bool
    readyChan        chan struct{}
    pushMu           sync.Mutex   // 防止 runParallel 重入堆积
}
```

**推送生命周期**：

```
Start(ctx) → setupEventListeners() → initSubscriptions() → go pushLoop()
                                                                    │
                              ┌─────────────────────────────────────┘
                              ▼
                    等待 readyChan（前端就绪信号）
                              │
                              ▼
                    立即并行推送一次（冷启动）
                              │
                              ▼
              ┌───────┬───────┬────────┬──────────┐
              ▼       ▼       ▼        ▼          ▼
          fastTicker normal slow  klineDay    stopChan
          (1s)     (3s)  (30s)  (5min)
```

**时段自适应**由 `getMarketPhase()` 决定（交易中/集合竞价/午休/收盘），不同阶段的推送内容与频率不同。详见 [01-架构总览.md](01-架构总览.md#61-实时行情推送)。

Web 模式下新增了三个公开订阅方法，供 HTTP 层直接驱动：

```go
func (p *MarketDataPusher) SetStockSubscriptions(codes []string)
func (p *MarketDataPusher) SetOrderBookSubscription(code string)
func (p *MarketDataPusher) SetKLineSubscription(code, period string)
```

### 2.4 `session_service.go` / `strategy_service.go`

| 服务 | 存储 | 说明 |
|------|------|------|
| `SessionService` | `<dataDir>/sessions/<code>.json` | 每只股票一个会话文件 |
| `StrategyService` | `<dataDir>/strategies.json` | 策略仓库，含内置策略初始化 |

`SessionService` 用 `stockCode` 作为文件名，会话内消息按时间追加。

### 2.5 其他服务

| 文件 | 职责 |
|------|------|
| `f10_service.go` | 东方财富 F10 数据抓取与解析 |
| `news_service.go` | 财联社快讯 |

## 3. `internal/adk` — Agent 运行时

基于 Google ADK（Agent Development Kit）封装。

### 3.1 `model_factory.go` — 模型工厂

```go
switch config.Provider {
case models.AIProviderGemini:    // Gemini 原生
case models.AIProviderVertexAI:  // Vertex AI
case models.AIProviderOpenAI:    // OpenAI 兼容（含 DeepSeek/Kimi/GLM/通义…）
case models.AIProviderAnthropic: // Anthropic Messages API
}
```

OpenAI 兼容模式下，`BaseURL` 决定实际后端，因此同一个 provider 能接绝大多数国产模型。

### 3.2 `expert_builder.go` — 专家构造

把 `AgentConfig` 转成 ADK 的 Agent：

- `Instruction` → 系统提示词
- `Tools` → 工具白名单（未勾选的工具不会被 Agent 看到）
- `AIConfigID` → 解析出具体模型实例
- 注入该股票的实时上下文（价格、涨跌、持仓）

### 3.3 `tools/` — 工具集

37 个工具，注册在 `registry.go`：

```go
func (r *Registry) registerAllTools() {
    r.registerTool("get_stock_realtime", "获取股票实时行情数据...", r.createStockRealtimeTool)
    // ...
}
```

每个工具是 ADK 的 `tool.Tool` 实现，闭包里持有对应 service。工具函数的返回值是给 LLM 看的文本/JSON。

工具文件按域拆分：`f10.go`（21 个 F10 工具）、`market_extra.go`、`market_fundflow.go`、`news.go`、`hottrend.go`、`kline.go`、`longhubang.go`、`orderbook.go`、`research_report.go`、`search.go`、`stock_context.go`、`stock_realtime.go`、`f10_sections.go`、`f10_extra.go`。

### 3.4 `mcp/manager.go` — MCP 管理

```go
type Manager struct {
    configs   []models.MCPServerConfig
    servers   map[string]*mcpServer
    toolset   tool.Toolset
}
```

- `LoadConfigs()` 加载配置
- `Initialize(ctx)` 预创建 toolset（必须在 App 启动时调用）
- 支持 http / sse / command 三种传输

### 3.5 `anthropic/` / `openai/` — 厂商适配

处理各厂商 API 的消息格式差异、思考块解析（`think_parser.go`）、token 参数兼容（`openai_token_compat.go`：max_tokens vs max_completion_tokens）。

## 4. `internal/meeting` — 会议室编排

```
meeting/
├── service.go    核心服务
└── moderator.go  "小韭菜"——意图分析与专家选择
```

`meeting.Service` 职责：

1. 接收用户消息 → 解析意图（是否 @ 了特定专家）
2. 选定专家集合
3. 按 `smart`/`direct` 模式编排讨论
4. 每个专家发言后通过事件推送
5. 失败自动重试（`SetRetryCount`）
6. 可选二次复核
7. 结果写入记忆

配置注入点：

```go
meetingService.SetAIConfigResolver(a.getAIConfigByID)  // 模型解析
meetingService.SetMemoryManager(memoryManager)          // 记忆
meetingService.SetModeratorAIConfig(cfg)                // 小韭菜模型
meetingService.SetMemoryAIConfig(cfg)                   // 摘要模型
meetingService.SetRetryCount(n)
meetingService.SetVerboseAgentIO(bool)
meetingService.SetAgentSelectionStyle(style)
meetingService.SetEnableSecondReview(bool)
```

## 5. `internal/memory` — 记忆系统

```
memory/
├── manager.go      记忆管理：压缩、事实提取、相关性排序
├── storage.go      文件存储（<dataDir>/memories/<code>.json）
├── relevance.go    相关性评分
└── ...
```

`Config` 控制行为：

```go
type Config struct {
    MaxRecentRounds   int
    MaxKeyFacts       int
    MaxSummaryLength  int
    CompressThreshold int
}
```

流程：对话累积 → 超过 `CompressThreshold` 触发压缩 → LLM 提取关键事实 + 生成摘要 → 覆盖写回。

## 7. `internal/pkg` — 基础设施

### 7.1 `pkg/paths` — 目录解析

```go
func GetDataDir() string
// 优先级：$JCPDATA_DIR → os.UserConfigDir()/jcp → ./.data
```

`GetCacheDir()` / `EnsureCacheDir(subDir)` 用于缓存目录。

### 7.2 `pkg/proxy` — 代理管理

按运行形态取代理：

```go
switch runtime.GOOS {
case "windows": return m.getWindowsProxy(scheme)  // 读注册表 ProxyEnable/ProxyServer
case "darwin":  return m.getMacOSProxy()
default:        return ""   // Linux 依赖环境变量
}
```

`newCommand` 在 Windows 下额外设 `SysProcAttr.HideWindow = true` 隐藏子进程窗口（`cmd_windows.go` / `cmd_unix.go`）。

### 7.3 `pkg/eventbus` — 事件总线（新增）

```go
type EventBus interface {
    Emit(ctx context.Context, name string, data any)
    On(name string, handler Handler) func()
    Listen(ctx context.Context, name string, fn SubscribeFunc) func()
    Off(name string)
    Close()
}
```

三个实现：

| 实现 | build tag | 行为 |
|------|-----------|------|
| `WailsBus` | `!web` | 转发 `runtime.EventsEmit` |
| `WebBus` | `web` | 投递到 Hub，由 SSE 写出端推给浏览器 |
| `NopBus` | — | 空实现，测试与单命令模式 |

Hub 负责按订阅键过滤，详见 [06-事件流.md](06-事件流.md)。

### 7.4 `pkg/platform` — 平台能力（新增）

```go
type Desktop interface {
    OpenURL(ctx context.Context, url string)
    WindowMinimise(ctx context.Context)
    WindowToggleMaximise(ctx context.Context)
    Quit(ctx context.Context)
}
```

`WailsDesktop`（`!web`）转发 Wails runtime；`WebDesktop`（`web`）全部空操作。

## 8. `app.go` — 应用装配

`App` 结构体持有全部服务实例，是依赖注入的中心。

```go
type App struct {
    ctx               context.Context
    configService     *services.ConfigService
    marketService     *services.MarketService
    newsService       *services.NewsService
    f10Service        *services.F10Service
    hotTrendService   *hottrend.HotTrendService
    longHuBangService *services.LongHuBangService
    marketPusher      *services.MarketDataPusher
    meetingService    *meeting.Service
    sessionService    *services.SessionService
    strategyService   *services.StrategyService
    agentContainer    *agent.Container
    toolRegistry      *tools.Registry
    mcpManager        *mcp.Manager
    memoryManager     *memory.Manager
    updateService     *services.UpdateService
    openClawServer    *openclaw.Server

    bus     eventbus.EventBus   // 新增
    desktop platform.Desktop    // 新增
}
```

### 构造

```go
func NewApp() *App                                  // 桌面模式
func NewAppWithDeps(bus, desktop) *App              // Web 模式注入
```

`NewAppWithDeps` 是 Web 化的关键——它让上层业务代码完全不感知运行形态。

### 生命周期

```go
func (a *App) Startup(ctx context.Context)   // 桌面模式由 wails.Run 回调，Web 模式手动调用
func (a *App) Shutdown(ctx context.Context)
```

`Startup` 做四件事：初始化代理、初始化 MCP、设置 AI 配置解析器、启动市场推送。

### 公开方法

App 上共有 70 个导出方法，其中 **60 个构成 HTTP API**（详见 [05-API-接口.md](05-API-接口.md)），
另有 Web 模式专用的 3 个订阅方法（`SetStockSubscriptions` / `SetOrderBookSubscription` / `SetKLineSubscription`），
以及 `Greet`、`WindowMinimize` 等桌面专属方法。

API 端点按域分组：

| 分组 | 方法数 | 代表 |
|------|-------|------|
| 配置 | 4 | `GetConfig` `UpdateConfig` |
| 自选股 | 3 | `GetWatchlist` `AddToWatchlist` |
| 行情 | 8 | `GetKLineData` `GetOrderBook` |
| F10 | 2 | `GetF10Overview` |
| 会话持仓 | 5 | `GetOrCreateSession` `UpdateStockPosition` |
| Agent 配置 | 4 | `GetAgentConfigs` |
| 策略 | 8 | `GetStrategies` `GenerateStrategy` |
| 会议室 | 6 | `SendMeetingMessage` `RetryAgent` |
| MCP | 7 | `GetMCPServers` `TestMCPConnection` |
| 舆情榜单 | 8 | `GetHotTrend` `GetLongHuBangList` |
| 版本更新 | 4 | `CheckForUpdate` `DoUpdate` |

## 9. 依赖装配顺序

`NewAppWithDeps` 中的顺序不可随意调整：

```
1. paths.GetDataDir()           → 数据目录
2. logger.InitFileLogger()      → 日志（要在其它服务之前）
3. services.NewConfigService()  → 配置（其它服务依赖它）
4. 各数据服务（research/f10/hottrend/market/news/longhubang）
5. tools.NewRegistry(...)       → 工具集（依赖上面全部）
6. mcp.NewManager() + LoadConfigs
7. meeting.NewServiceFull(toolRegistry, mcpManager)
8. memory.NewManagerWithConfig() → 记忆（依赖 configService 的 memory 配置）
9. sessionService / strategyService
10. agent.NewContainer() + LoadAgents()
11. updateService / openClawServer
```
