# 01 · 架构总览

## 1. 系统定位

韭菜盘（JCP）是一个**多 Agent 协作的股票分析系统**。用户选定股票后，系统调度多个专家角色（技术面、资金面、基本面、消息面……）围绕该股进行讨论，最终产出分析结论。

它解决的核心问题是：**单个 LLM 对股票的分析缺乏多视角交叉验证**。JCP 把"投资委员会"模式搬进软件——每个专家有独立的角色定义、提示词、可用工具和记忆，多轮讨论后相互补充。

## 2. 两种运行形态

同一套业务代码支持两种形态，通过 Go build tag 分离。

| | 桌面模式 | Web 服务模式 |
|---|---|---|
| 入口 | `main.go`（`//go:build !web`） | `web_main.go`（`//go:build web`） |
| 构建 | `go build .` 或 `wails build` | `go build -tags web` |
| 界面 | Wails 原生窗口（WebView） | 浏览器 |
| 通信 | Wails IPC 绑定 | HTTP REST + SSE |
| 事件分发 | `runtime.EventsEmit` | Server-Sent Events |
| 桌面专属能力 | 窗口控制、外部浏览器 | 降级为空操作 |
| 典型场景 | 个人本地使用 | 服务器部署、多人访问 |

**关键点**：两种形态下 `App` 结构体的 60 个方法完全一致，差异只在"如何调用"与"如何接收事件"两个方向。

```
              ┌─────────────────────────────────────┐
              │  App（60 个方法，业务逻辑唯一实现）  │
              └──────────────┬──────────────────────┘
                             │
        ┌────────────────────┴────────────────────┐
        │                                          │
  ┌─────┴──────┐                          ┌────────┴────────┐
  │ 桌面模式    │                          │  Web 模式        │
  │ Wails 绑定 │                          │ HTTP + SSE      │
  └─────┬──────┘                          └────────┬────────┘
        │                                          │
   ┌────┴────┐                              ┌──────┴──────┐
   │ eventbus│ (WailsBus)                   │ eventbus    │ (WebBus)
   │ platform│ (WailsDesktop)               │ platform    │ (WebDesktop)
   └─────────┘                              └─────────────┘
```

## 5. 核心概念

### 5.1 股票代码格式

全系统统一使用**带交易所前缀**的 6 位代码：

| 格式 | 含义 | 示例 |
|------|------|------|
| `sh600000` | 上海证券交易所 | 浦发银行 |
| `sz000001` | 深圳证券交易所 | 平安银行 |
| `sh000001` | 上证指数 | — |
| `sz399001` | 深证成指 | — |
| `sz399006` | 创业板指 | — |

代码是**贯穿全系统的主键**：会话、记忆、订阅、缓存均以它为键。

### 5.2 Agent（专家）

专家是 JCP 的核心抽象，定义在 `internal/models` 的 `AgentConfig`：

```go
type AgentConfig struct {
    ID           string   `json:"id"`
    Name         string   `json:"name"`         // 显示名，如"技术面分析师"
    Role         string   `json:"role"`         // 角色定位
    Avatar       string   `json:"avatar"`       // 头像标识
    Color        string   `json:"color"`        // 主题色
    Instruction  string   `json:"instruction"`  // 系统提示词 —— 专家行为的核心
    Tools        []string `json:"tools"`        // 可用工具名白名单
    MCPServers   []string `json:"mcpServers"`   // 可用 MCP 服务器
    Enabled      bool     `json:"enabled"`
    AIConfigID   string   `json:"aiConfigId"`   // 使用的模型配置
}
```

要点：

- `Instruction` 决定专家的思考方式与输出风格
- `Tools` 是白名单——专家只能调用被授权的工具，实现"角色隔离"
- `AIConfigID` 让不同专家可用不同模型（如技术面用强推理模型、成本控制用便宜模型）

专家按**策略**（`Strategy`）组织，一个策略包含一组专家 + 启停配置。

### 5.3 策略（Strategy）

```
Strategy
├── id / name / description / color
├── agents[]      该策略包含哪些专家
├── isBuiltin     是否内置
└── source        来源：user / builtin / ai
```

激活策略 ID 存在 `AppConfig` 里，全局只有一个生效。切换策略会触发 `strategy:changed` 事件。

### 5.4 会话与记忆

| 概念 | 粒度 | 存储位置 |
|------|------|---------|
| 会话（Session） | 每只股票一个 | `sessions/<code>.json` |
| 记忆（Memory） | 每只股票一份 | `memories/<code>.json` |

会话存**聊天记录**（谁在第几轮说了什么），记忆存**跨会话的长期认知**——关键事实、历史摘要、近期对话轮次。记忆系统可用独立的 LLM 做压缩与摘要。

### 5.5 AI 配置

```go
type AIConfig struct {
    ID, Name, Provider string
    BaseURL   string   // 自定义端点（OpenAI 兼容接口填这里）
    APIKey    string   // 明文存储于服务端，浏览器只拿到掩码
    ModelName string
    MaxTokens int
    Temperature float64
    Timeout   int
    IsDefault bool
    UseResponses bool  // OpenAI Responses API 开关
    NoSystemRole  bool  // 不支持 system role 的模型
    Project, Location, CredentialsJSON string  // Vertex AI 专用
}
```

支持的 Provider：`openai`（兼容 OpenAI/Gemini/DeepSeek/Kimi/GLM 等绝大多数服务）、`gemini`、`vertexai`、`anthropic`。

## 6. 核心数据流

### 6.1 实时行情推送

```
浏览器                     Go 服务端                        外部
  │                          │                              │
  │  GET /api/events (SSE)  │                              │
  │◄─────────────────────────┤                              │
  │                          │                              │
  │  POST /api/market/       │                              │
  │      subscribe           │                              │
  │─────────────────────────►│  设置订阅集合                 │
  │                          │                              │
  │  GET /api/frontend/ready │                              │
  │─────────────────────────►│  启动推送循环 ────────────────►│
  │                          │  拉取行情（TDX 协议）          │
  │                          │◄──────────────────────────────│
  │                          │                              │
  │  data: {event, data}    │                              │
  │◄─────────────────────────┤                              │
```

推送频率按交易时段自适应：

| 时段 | 盘口 | 股票/指数 | K线 |
|------|------|----------|------|
| 交易中 | 1 秒 | 3 秒 | 5 分钟线 3 秒 |
| 集合竞价 | — | 9 秒 | — |
| 午休 | — | 15 秒 | — |
| 收盘 | — | 30 秒 | 日线 5 分钟 |

### 6.2 AI 会议（多 Agent 讨论）

```
用户提问
  │
  ├─ meeting.Service 分派
  │    ├─ smart 模式：串行讨论，每位专家看到前一位的发言
  │    └─ direct 模式：独立回答，互不可见
  │
  ├─ adk 构造 Agent（角色 + 提示词 + 工具白名单 + 模型）
  │
  ├─ Agent 调用工具（get_stock_realtime / get_f10_valuation / …）
  │    └─ 工具执行时按股票代码注入实时上下文
  │
  ├─ 发言以 SSE 事件推送：meeting:message:<code>
  │    └─ 前端实时渲染，前端也可 EventsOn 监听
  │
  ├─ 失败自动重试（AIRetryCount）
  │
  └─ 可选：二次复核（EnableSecondReview）
       └─ memory 写入关键事实与摘要
```

## 7. 扩展点

| 扩展方向 | 位置 | 做法 |
|---------|------|------|
| 新增行情工具 | `internal/adk/tools/` | 实现 `tool.Tool`，在 `registry.go` 注册 |
| 新增数据源 | `internal/services/` | 参考 `market_provider_tdx.go` 的 Provider 模式 |
| 新增模型厂商 | `internal/adk/model_factory.go` | 加 provider 分支 + 适配器 |
| 外部工具接入 | MCP | 在界面配置 MCP 服务器，无需改代码 |
| 新增专家角色 | 界面配置 | 填角色提示词 + 勾选工具 |
| 自定义 AI 端点 | `AIConfig.BaseURL` | 任何 OpenAI 兼容服务 |
